# 105. Feedback — `retry-word` + `complete` 응답 형태 정렬 (D9)

## Goal

FRONT_API_SPEC §8 정렬: `POST /api/feedback/{feedbackId}/retry-word` 는 `RetryWordResult`, `POST /api/feedback/{feedbackId}/complete` 는 갱신된 `User` 를 반환해야 한다. 현재 둘 다 `ApiResponse<FeedbackDetailResponse>` 를 반환 — 프론트가 retry 결과의 `correct` / `score` 필드와 complete 후 갱신된 user stats (`exp`/`streak`) 를 받지 못한다.

## Prerequisites

- 100 (envelope-and-error-shape).
- 101 (auth-dto-alignment) — `User` DTO shape 이 먼저 spec 정합되어야 complete 응답이 spec 정합.

## Acceptance Criteria

- [ ] `src/main/java/.../pronunciation/feedback/dto/RetryWordResult.java` (신규):
  - record `RetryWordResult(boolean correct, List<String> perceived, List<String> canonical, double score, String guidanceKr)` — 정확히 5 필드 (FRONT_API_SPEC §12).
  - `word` / `stepScore` 필드 없음 (read-only retry, 저장 안 함).
- [ ] `FeedbackController.retryWord`:
  - 반환 타입 `ApiResponse<FeedbackDetailResponse>` → `ApiResponse<RetryWordResult>`.
  - `FeedbackService.retryWord(userId, feedbackId, audio)` 반환 타입도 `RetryWordResult` 로 변경.
- [ ] `FeedbackController.complete`:
  - 반환 타입 `ApiResponse<FeedbackDetailResponse>` → `ApiResponse<UserResponse>`.
  - `FeedbackService.complete(userId, feedbackId)` 가 보상 가산 후 갱신된 `UserResponse` 반환.
  - `MemberService.awardCompletionRewards(...)` 호출 시 갱신된 `User` 받아 → `UserResponse.from(...)`.
- [ ] `FeedbackService.retryWord` 본문:
  - `correct = (perceived equals canonical)`.
  - `score` = ScoringPolicy.singleWordScore(...).
  - `guidanceKr` = `LlmClient.retryGuidance(...)`.
- [ ] `FeedbackControllerTest.java`:
  - retry-word: 응답 assertion `$.data.correct` / `$.data.perceived` / `$.data.canonical` / `$.data.score` / `$.data.guidanceKr` (5 필드). FeedbackDetailResponse 의 `id`/`accuracy` 등 검증 제거.
  - complete: 응답 assertion `$.data.username` / `$.data.streak` / `$.data.exp` (UserResponse 필드).
- [ ] `./gradlew compileJava compileTestJava` 그린.
- [ ] **pre-commit 훅 통과**.
- [ ] `rg -n "FeedbackDetailResponse.*retryWord|retryWord.*FeedbackDetailResponse" src/main` 0 hits.
