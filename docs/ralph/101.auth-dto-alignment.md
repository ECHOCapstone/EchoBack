# 101. Auth — TokenResponse + Login/Check request DTO 정렬 (D5+D6+D7)

## Goal

FRONT_API_SPEC §2 + §12 정렬: 토큰 응답을 `{ accessToken, tokenType, expiresInSec, user }` 으로, 로그인 요청을 `{ username, password }` 으로, 중복확인 요청을 `{ value }` 로 정렬한다. 현재 backend 는 각각 `{ token, expiresAt, profile }`, `{ usernameOrEmail, password }`, `{ username }` / `{ email }` 을 사용 — 프론트가 보낸 그대로 받지 못해 모든 가입/로그인 흐름이 깨진다.

## Prerequisites

- 100 (envelope-and-error-shape) — 응답 envelope 형태가 먼저 정렬되어야 응답 assertion 이 깨끗하다.

## Acceptance Criteria

- [ ] `member/dto/AuthTokenResponse.java`:
  - record 필드 = `(String accessToken, String tokenType, long expiresInSec, UserResponse user)`.
  - 기존 `token` / `expiresAt` / `profile` 필드 제거.
  - `tokenType` 은 항상 `"Bearer"` (정적 팩토리에서 상수 주입).
  - `expiresInSec` 은 토큰 만료까지 남은 초 (long; `Instant.now()` 기준 차이로 계산하거나 JWT exp claim 직접 이용).
- [ ] `member/dto/LoginRequest.java`:
  - 필드 `username` (NotBlank) + `password` (NotBlank).
  - 기존 `usernameOrEmail` 필드 제거.
- [ ] check-username 요청 DTO (이름 `UsernameCheckRequest` 또는 유사):
  - 단일 필드 `value` (NotBlank).
- [ ] check-email 요청 DTO 유사 — `value` 단일 필드.
- [ ] `AuthService.login` 본문: `req.username()` 사용. username으로만 lookup (email mixed login 정책은 본 PR 범위 외 — spec 따라 username only).
- [ ] `AuthService.signup` / `loginGoogleDemo` 의 `TokenResponse` 빌드: 새 필드명 + 정적 팩토리 `AuthTokenResponse.of(jwt, user, ttlSec)` 또는 record canonical constructor 직접 호출.
- [ ] `AuthController` 의 컨트롤러 시그니처 `RequestBody` 타입은 그대로 (record 내부 구조만 바뀜).
- [ ] 테스트 갱신:
  - `AuthControllerTest`: signup/login/oauth-demo 의 응답 jsonPath = `$.data.accessToken` / `$.data.tokenType` / `$.data.expiresInSec` / `$.data.user.username` 등.
  - check-username/check-email 테스트: 요청 JSON `{"value":"alice"}` 로.
  - 로그인 테스트: 요청 JSON `{"username":"alice","password":"..."}`.
  - `MemberControllerTest` 의 `$.data.id` / `$.data.username` 등 (UserResponse 가 spec 정합인지 확인).
- [ ] `./gradlew compileJava compileTestJava` 그린.
- [ ] **pre-commit 훅 통과**.
- [ ] `rg -n "usernameOrEmail|expiresAt.*Instant|profile.*UserResponse" src/main` 0 hits.
