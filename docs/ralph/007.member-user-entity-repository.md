# 007. Member — User 엔티티 및 UserRepository

## Goal
회원·인증·통계 도메인이 공통 의존하는 `User` JPA 엔티티와 `UserRepository` lookup 메서드를 도입한다.

## Prerequisites
- 001: foundation-api-response-errors

## Acceptance Criteria
- [ ] `com.capstoneecho.echo_back.member.entity.User` 엔티티 (`@Table(name="users")`):
  - 필드: `id`(PK), `username`(unique), `email`(unique), `passwordHash`(BCrypt, null 허용 — OAuth2 only 케이스), `nickname`, `streak`(0..7), `exp`, `lastStudyAt`(Instant).
  - 정적 팩터리: `User.signup(username, email, passwordHashBCrypt, nickname)`, `User.fromOAuth2(email, nickname)`.
  - 도메인 메서드: `updateNickname(...)`, `mergeOAuth2Login()`, `recordCompletion(now, expReward, statsZone)` (streak day 경계 KST 처리 — IMPLEMENTATION_PLAN §2.2).
  - 비밀번호 평문 setter 금지, BCrypt 해시만 받음.
- [ ] `UserRepository extends JpaRepository<User, Long>` 메서드: `findByUsername`, `findByEmail`, `existsByUsername`, `existsByEmail`.
- [ ] `UserRepositoryDataJpaTest` (`@DataJpaTest`) 가 lookup/exists 4메서드 그린.
- [ ] `User.signupTest` 가 정적 팩터리 불변식(비밀번호 해시 형식, 닉네임 nullable) 그린.
- [ ] `./gradlew test --tests UserRepositoryDataJpaTest --tests UserSignupTest` 그린.
