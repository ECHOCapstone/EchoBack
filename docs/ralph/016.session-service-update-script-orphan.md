# 016. Session — SessionService (CRUD + updateScript orphan 처리)

## Goal
세션 CRUD 및 스크립트 갱신 시 sentence 통째 교체를 담당하는 서비스를 도입한다. IMPLEMENTATION_PLAN §7.2 의 서비스 도메인 불변식 #5(이력 보존), #6(스냅샷 보존) 을 본 task 가 책임진다.

## Prerequisites
- 015: session-entities-user-scoped-repository

## Acceptance Criteria
- [ ] `SessionService` (`@Service`, `@Transactional`):
  - `list(userId): List<SessionSummaryResponse>`.
  - `create(userId, request): SessionDetailResponse` — title 만 입력. `Session.create(user, title)`.
  - `get(userId, sessionId): SessionDetailResponse` — 미존재/타인 세션 시 `SESSION_NOT_FOUND`.
  - `patch(userId, sessionId, request): SessionDetailResponse` — null 필드 미반영. scriptText 변경 시 `Session.updateScript(...)` 호출.
  - `delete(userId, sessionId)` — `deleteByIdAndUser_Id` 결과가 0 이면 `SESSION_NOT_FOUND`.
- [ ] `SentenceSplitter` 컴포넌트 — 1차에 마침표·줄바꿈 기준 split (IMPLEMENTATION_PLAN §3.2 위험·결정 항목).
- [ ] 서비스 도메인 불변식 테스트 (`@SpringBootTest` + `@Transactional`):
  - **#5**: Session.updateScript 후 기존 Recording.session_sentence_id 가 `SET NULL` 되었지만 Recording 행은 보존되어 조회 가능. (실제 Recording 엔티티는 task 018 이후 존재 → 본 task 는 sentence orphan-remove + Recording FK 정책만 SQL 마이그레이션 또는 schema 단에서 확인. 실 Recording 연동 검증은 task 023 의 연관 테스트로 위임 가능.)
  - **#6**: session 하드 삭제 후 PronunciationFeedback 의 session 스냅샷 필드(title, scriptText) 가 보존됨을 검증. (Feedback 엔티티는 task 019 후 → 본 task 는 Session 삭제 동작과 cascade 정책만 검증. 실 Feedback 보존 검증은 task 026 의 통합 테스트에 추가.)
  - PATCH null 필드 미반영.
- [ ] `./gradlew test --tests SessionServiceTest` 그린.
