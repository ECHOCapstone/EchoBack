# 100. Envelope — 응답 봉투 형태 정렬 (D4)

## Goal

FRONT_API_SPEC §1 정렬: 모든 JSON 응답이 `{ success, data, error }` 구조여야 하며, `error` 는 `null` 또는 중첩 `{ code, message }`. 현재 `ApiResponse` 는 평탄 `errorCode`/`errorMessage` 두 필드를 사용하고 `@JsonInclude(NON_NULL)` 이 envelope 키도 omit 한다. 본 task 가 이 envelope 을 source-of-truth contract 와 정렬하며, 영향 받는 모든 controller 테스트의 jsonPath assertion 을 sweep 한다.

## Prerequisites

- 없음. 본 task 는 다른 모든 task (101-107) 의 hard blocker.

## Acceptance Criteria

- [ ] `global/common/ApiResponse.java` 가 record `ApiResponse<T>(boolean success, T data, ApiError error)` 형태 (또는 record 내부 record `Error(String code, String message)`). 평탄 `errorCode` / `errorMessage` 두 필드는 제거.
- [ ] 클래스 레벨 `@JsonInclude(NON_NULL)` 제거 — envelope `data` 와 `error` 키는 항상 직렬화되어야 한다 (FRONT_API_SPEC §1 discriminated-union type).
- [ ] 정적 팩토리 API `ApiResponse.success(T)` / `ApiResponse.failure(ErrorCode, String)` / `ApiResponse.success()` 시그니처 유지 — 호출부 변경 최소화.
- [ ] `global/common/GlobalExceptionHandler.java` 가 새 `error` nested 형태로 payload 빌드. ErrorCode 매핑 로직 변경 없음 — payload 모양만 갱신.
- [ ] 모든 `*ControllerTest.java` 의 envelope 실패 assertion 갱신:
  - `jsonPath("$.errorCode")` → `jsonPath("$.error.code")`
  - `jsonPath("$.errorMessage")` → `jsonPath("$.error.message")`
- [ ] 성공 케이스 assertion 변경 옵션: `jsonPath("$.data").exists()` + `jsonPath("$.error").value(nullValue())`. 회귀 보호 위해 최소 1-2개 controller 에서 `$.error` null 검증 추가.
- [ ] REST Docs 응답 필드 description 갱신: `response-fields` snippet 에서 `errorCode` / `errorMessage` 항목을 `error.code` / `error.message` 로.
- [ ] `./gradlew compileJava compileTestJava` 그린.
- [ ] **pre-commit 훅 통과** — `./gradlew test` 는 commit 시점에 hook 이 자동 실행. agent 가 직접 호출하지 않는다.
- [ ] `rg -n "errorCode|errorMessage" src/main` 0 hits (envelope source 외).
- [ ] `rg -n "errorCode|errorMessage" src/test` 0 hits.

## TDD Entry Points

- 본 task 는 RED-then-GREEN 이 자연스럽게 일어남: ApiResponse 형태 변경 → 기존 jsonPath assertion 이 빨개짐 → 새 assertion 으로 갱신.
- 핵심 회귀 보호 테스트: 어느 한 controller (e.g., `AuthControllerTest.signupValidationFails`) 에서 `$.error.code` / `$.error.message` 둘 다 verify.
- 성공 케이스: `HealthControllerTest` 또는 `MemberControllerTest.me` 에서 `$.error` 가 null 임을 명시 verify.
