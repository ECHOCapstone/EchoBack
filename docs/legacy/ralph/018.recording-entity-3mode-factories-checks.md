# 018. Recording — Recording 엔티티 3-mode 정적 팩터리 + CHECK 제약 + Repository

## Goal
녹음 도메인의 `Recording` 엔티티를 3-mode(XOR) 안전성으로 도입한다. IMPLEMENTATION_PLAN §7.2 서비스 도메인 불변식 #2, #4 본 task 책임.

## Prerequisites
- 015: session-entities-user-scoped-repository

## Acceptance Criteria
- [ ] `Recording` (`@Table(name="recordings")`) 필드: `id`, `user`(@ManyToOne LAZY), `script`(@ManyToOne LAZY, nullable), `step`(@ManyToOne LAZY, nullable, `ON DELETE SET NULL`), `session`(@ManyToOne LAZY, nullable, `ON DELETE SET NULL`), `sessionSentence`(@ManyToOne LAZY, nullable, `ON DELETE SET NULL`), `audioPath`, `targetTextSnapshot`, `durationSec`, `perceived`(text), `canonical`(text), `peakSoftmax`(json/text), `errorsJson`(text), `stepScore`(int), `guidanceKr`(text), `wrongWordsJson`(text), `createdAt`.
- [ ] DB CHECK 제약(JPA `@Check` 또는 schema.sql):
  - `(script_id IS NULL AND session_id IS NULL) OR ((script_id IS NULL) <> (session_id IS NULL))`
  - `step_id IS NULL OR script_id IS NOT NULL`
  - `session_sentence_id IS NULL OR session_id IS NOT NULL`
- [ ] 정적 팩터리 3개, 각각 cross-parent 거부 + app 레벨 검증:
  - `Recording.forScriptStep(user, script, step, snapshot...)` — step.script != script 이면 `IllegalArgumentException`.
  - `Recording.forSessionSentence(user, session, sentence, snapshot...)` — sentence.session != session 이면 거부.
  - `Recording.forSessionFreeForm(user, session, snapshot...)` — sessionSentence 미지정.
- [ ] `RecordingRepository extends JpaRepository<Recording, Long>`:
  - `findByIdAndUser_Id(id, userId)`.
  - `findAllByUser_IdAndScript_IdAndStep_IdOrderByCreatedAtAsc(...)`, `findAllByUser_IdAndSession_IdAndSessionSentence_IdOrderByCreatedAtAsc(...)` 등 generate/retry 에 필요한 조회.
- [ ] 서비스 도메인 불변식 테스트:
  - **#2** `RecordingFactoryTest::scriptStepFactoryRejectsCrossParent`, `sessionSentenceFactoryRejectsCrossParent`.
  - **#4** `RecordingCheckConstraintTest` 가 raw `EntityManager.createNativeQuery(INSERT ...)` 로 양쪽 NOT NULL 입력 시 DB 제약 위반 검증.
- [ ] `./gradlew test --tests RecordingFactoryTest --tests RecordingCheckConstraintTest` 그린.
